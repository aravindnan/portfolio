A blood test nobody explains

Liver scarring usually causes no symptoms until it is advanced, and a routine blood test is often the first sign. But a lab report is a column of numbers with no meaning for the person holding it.

Cirrh0 reads that report for you. It pulls the values out of the PDF, asks you to check them, and works out FIB-4, APRI and ALBI: the published formulas liver doctors already use to judge scarring and liver function. Each score comes with its band in words, how it was calculated, and the next question to ask your doctor.

It’s built for patients and carers before or after a doctor’s visit, and the sample reports follow Indian lab layouts and units.

Honest about what it knows

The first version reported a model accuracy of about 72%. When I audited it, that figure turned out to be inflated by data leakage. Measured properly, the model picks the right stage about half the time, against 38% for always guessing the most common stage.

So the design says so, in the place where people read their result:

  • A reliability note sits above every result: what the model was trained on, and how often it’s right.
  • The guideline scores come first. They are plain formulas, so the same values always give the same answer.
  • The stage is labelled Estimated stage (of 4), never a diagnosis. Bands use hedged words like “Indeterminate” and “Below the screening threshold”.
  • Every page carries the line “Demo project. Not medical advice.”

Plain words, one step at a time

  • Check before you trust. Extracted values land in an editable form that says “Values are read automatically and can be wrong”. Errors say exactly what to do: 2 values are still missing: Copper, Prothrombin time. Copy each one from your lab report.
  • Safety first. A warning-sign check lists seven symptoms. Tick any one and the page stops: Please get medical care today.
  • Learn by moving. The what-if tool lets you drag platelets or AST and watch the three scores change band. Each slider says whether lifestyle can move that value.
  • Trends that explain themselves. Each report becomes a point on a chart, and “What changed” splits a FIB-4 change into the share from each lab.

The visual language is calm and clinical: crimson League Spartan titles, flat tiles with square corners and no shadows, green, amber and red band tints, and a ring-and-dot logo.

Three services, one honest answer

Cirrh0 is three parts:

  • a React and TypeScript client;
  • an Express API on PostgreSQL through Prisma;
  • a Flask service that reads PDFs with pdfplumber and runs a CatBoost model trained on the Mayo Clinic PBC dataset.

The guideline scores live in one shared module on the API, so scoring, explanations and the trend chart’s cut-off lines can never disagree. The client mirrors the same formulas for the what-if tool, and a test keeps the two in sync.

The model runs on a free tier where it can be asleep. So a model outage never loses someone’s analysis: the guideline scores are saved anyway, and the result page says the estimate wasn’t available.

“What changed” works because FIB-4 is a product of powers, so its change splits exactly into each lab’s share.

The rebuild, by the numbers

In November I audited my own May prototype and rebuilt most of it:

  • Security. Gemini output used to be parsed with eval(), every endpoint was open, and a public route could delete all data. Now there’s cookie sessions, ownership checks, rate limits, an upload host allowlist, and 0 known npm vulnerabilities (there were 12).
  • Speed. The hero went from a 27.8 MB GIF to a 12 KB still. The main bundle went from 337 kB to 80 kB gzipped. Moving from Create React App to Vite brought the build under Render’s 512 MB limit.
  • Truth. The stage now comes from the model, not from text an LLM echoed back, and the published accuracy is the honest one.
  • Tests. API tests run against a real PostgreSQL, the model service has its own tests, and CI runs on every push.

Thirteen pages, ten API routes, three model endpoints, ten value explainers, seven warning signs, six sliders.
