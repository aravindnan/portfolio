Teach habits, not tools

CodeWalnut wrote The Guidebook to Agentic Engineering: twelve competencies for engineers who build with AI coding agents. The course turns that book into practice for CodeWalnut’s own engineers and for engineers at client companies.

A guidebook is easy to read and easy to forget. So the course is built around doing: every module asks you to recognise a habit, try it, and then use it on your own work that week.

There are twelve modules in four parts: Set up the workshop, Build with confidence, Ship with proof, Get better every cycle. Every module is open from the start, and the course suggests an order.

Eight steps, every time

Each module follows the same rhythm, so learners spend their attention on the idea, not on the interface:

  1. Overview. What you’ll be able to do.
  2. The Shift. A two-minute narrated video with a chaptered transcript.
  3. In Practice. Six rules, the common mistake, and a pro tip.
  4. See it in action. A before and after example.
  5. Knowledge check. Five scenarios. Pass with four, and every answer explains itself.
  6. Spot the error. Click the lines you think are wrong in a flawed file, then see what you caught and missed.
  7. Mission. Try the habit on your own work and write up what happened.
  8. Wrap-up. A private self-check, a toolkit and feedback.

On a phone, the outline folds into a “Step 3 of 8” drawer and Back and Next stay within thumb reach.

An editorial look, in three themes

The public site is editorial: a large display headline, a grid of twelve competency cards, and a warm porcelain, tangerine and blue palette. Signed in, it becomes a workbook, with a faint graph-paper grid, a sticky outline with a progress ring, and a reading column.

The type is Bricolage Grotesque for reading and Red Hat Mono for the interface. Learners can choose from three colour themes, three font pairs and sharp or rounded corners. That’s 18 combinations, all saved to their account.

Every theme is built 60/30/10 from colour roles, never raw hex values. A test checks every theme against WCAG AA contrast.

Grading the browser can't fake

Lessons are typed TypeScript objects, one file per module. Answer keys live in separate files marked server-only, so if a client component ever imports one, the build fails.

Exercises are graded by pure functions on the server. Spot the error, for example, compares the lines you flagged with the real errors and reports what you caught, missed and flagged by mistake.

Progress is merged on the server too. A graded step only counts as done if a passed attempt is on record, and the date you first finished a module is never overwritten.

The twelve module videos are made entirely in code too. Each transcript is narrated by Kokoro, an open text-to-speech model running locally. Each module has a React scene that Playwright steps through frame by frame at 1080p, and ffmpeg encodes the result. The narration and the on-page transcript come from the same text, so they can’t drift apart.

By the numbers

Built in ten days:

  • 12 modules, 36 exercises and 12 videos;
  • 10 database tables and 7 migrations;
  • unit tests, plus end-to-end and accessibility tests with Playwright and axe;
  • CI on every pull request.

It runs on Vercel, with a fully local mode for development that needs no hosted services.
