A percentage doesn't warn you

Most task tools show a completion ring: 85% done. That number looks reassuring right up until a deadline is missed. A project manager needs to know which task is about to slip, and why, while there’s still time to act.

TMS is a task manager for small teams. A manager creates a project, invites people into a workspace, and assigns tasks with a priority and a due date. Everyone moves their work across a board, comments, and gets notified when something that concerns them changes.

On top of that sits the part I cared most about: a risk radar that flags tasks before they slip, with the reasons spelled out.

Explain every flag

A risk score on its own is just another number to distrust. So every point of the score comes from a named reason, written as a sentence a manager could repeat in a stand-up:

  • Overdue by 3 days.
  • No activity for 8 days.
  • Due in 2 days but about 9 days of work left (typical for 5 similar finished tasks).

“Typical” comes from the project’s own finished tasks, not a fixed guess. Tasks of the same priority count first, then all tasks, then sensible defaults until there’s enough history. The board carries the same signal as small chips on each card, so nobody has to open the radar to notice.

Insights replace the completion ring with how work actually moves: cycle time, tasks finished per week, created versus completed, and the work that has sat longest in a column.

v1 to now

I designed v1 in 2023 for my master’s course: Inter, a deep teal-navy, a slim icon rail, grey chips, and coloured bars for priority. It looked tidy, but it was a static page of lists with lorem ipsum.

In 2026 I kept that visual language and rebuilt what it was for:

  • the board, the risk radar and insights as tabs on every project;
  • a task drawer that slides over the page, linkable by URL, with inline editing, a checklist, Markdown notes and history;
  • an activity feed with field-level changes;
  • an inbox that never notifies you about your own actions;
  • workspaces with roles and invite links;
  • a phone layout with its own top bar.

A heuristic you can read

The radar is deliberately not a black box. It’s a plain function that adds up named factors, such as schedule pressure, inactivity and an overloaded assignee, and returns each one as a reason.

The board feels instant because moves are optimistic. If the server refuses one, only that task goes back, and a screen reader hears what happened.

The rest:

  • Data. MongoDB moved to PostgreSQL with Prisma.
  • Caching. All server data goes through TanStack Query, with one table that says which cached data each request makes stale.
  • Sessions. httpOnly cookie sessions that can be revoked on the server.
  • Google sign-in. Checked properly, including against account pre-hijacking.
  • Delivery. CI deploys to Neon, Render and Vercel.

By the numbers

62 API routes, 12 data models, and 32 front-end test files with 290 test cases. The risk radar, insights, activity feed, inbox, task drawer and workspaces were all added in the 2026 rebuild, on top of the 2024 design.
